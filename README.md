# amnezia-key

Конвертер ключей AmneziaVPN: ссылка `vpn://`, JSON и конфиг `.conf` для AmneziaWG и WireGuard. Переводит ключ из любого формата в любой и заодно меняет IP и порт сервера.

В репозитории два инструмента с одной и той же логикой: страница `amnezia-key.html` с интерфейсом и консольная утилита `amnezia-key.js` для Node.js. Оба работают локально и без зависимостей, ключи никуда не отправляются.

> Неофициальный проект, не связан с командой AmneziaVPN.

## Зачем

Главный случай: у сервера сменился IP или порт, а у клиентов остались старые ключи. Адрес можно поменять прямо в ключе и не выпускать ключи заново. Кроме того, из ключа `vpn://` можно получить конфиг для приложений AmneziaWG и WireGuard или для роутера, собрать из `.conf` ключ для приложения AmneziaVPN или просто посмотреть, что лежит внутри ключа.

## Форматы

| Формат | Что это | Где используется |
|---|---|---|
| `link` | ключ `vpn://…` | приложение AmneziaVPN, файлы `.vpn` |
| `json` | тот же ключ в раскодированном виде | просмотр и ручная правка |
| `conf` | конфиг с секциями `[Interface]` и `[Peer]` | AmneziaWG, WireGuard, роутеры |

Формат входа определяется автоматически, формат выхода выбирается.

## Веб-страница

Откройте `amnezia-key.html` в браузере, установка и интернет не нужны. Вставьте ключ в поле «Вход» или перетащите туда файл `.vpn`, `.json` или `.conf`. В средней колонке укажите новый IP, порт или имя сервера: в пустых полях подсказкой видны текущие значения из ключа, а ниже показан адрес «было» и «стало». Формат результата выбирается радиокнопками над полем «Выход», результат можно скопировать или сохранить файлом.

Файл `.conf` сохраняется с именем по IP клиента, например `awg-10.8.1.6.conf`. AmneziaWG и WireGuard берут имя туннеля из имени файла, а в Linux оно ограничено 15 символами.

Нужен браузер с поддержкой Compression Streams API: Chrome или Edge 80+, Firefox 113+, Safari 16.4+.

## Консольная утилита

Нужен Node.js 16 или новее, зависимостей нет.

```
node amnezia-key.js [опции] [ВХОД]
```

`ВХОД` — это ключ `vpn://…`, путь к файлу `.vpn`, `.json` или `.conf` либо `-`. Если вход не указан или указан `-`, данные читаются из stdin.

| Опция | Что делает |
|---|---|
| `-i`, `--ip <IP>` | новый адрес сервера |
| `-p`, `--port <порт>` | новый порт сервера |
| `-f`, `--format <link\|json\|conf>` | формат вывода, по умолчанию `link` |
| `-n`, `--name <имя>` | название сервера в AmneziaVPN (для `link` и `json`) |
| `-o`, `--out <файл>` | записать результат в файл, а не в stdout |
| `-h`, `--help` | показать справку |

```sh
# поменять IP в ключе и получить новый ключ
node amnezia-key.js -i 203.0.113.10 vpn://...

# ключ -> конфиг AmneziaWG с новым IP и портом
node amnezia-key.js -i 203.0.113.10 -p 51820 -f conf -o client.conf vpn://...

# конфиг -> ключ для AmneziaVPN (файл .vpn тоже импортируется в приложение)
node amnezia-key.js -n "Домашний сервер" -o client.vpn client.conf

# посмотреть, что внутри ключа
node amnezia-key.js -f json client.vpn

# через конвейер
cat client.conf | node amnezia-key.js -i 203.0.113.10
```

Сводка (сервер, протоколы, адрес «было → стало») печатается в stderr, а в stdout идёт только результат, поэтому его можно перенаправить в файл или передать дальше по конвейеру. В Windows PowerShell 5.1 сохраняйте результат через `-o`, а не через `>`: иначе файл запишется в UTF-16 и не откроется.

## Как устроен ключ `vpn://`

Ключ — это префикс `vpn://` и строка base64url без `=`. В ней закодирован результат Qt-функции `qCompress`: четыре байта длины JSON (big-endian) и за ними поток zlib. Внутри лежит JSON с настройками сервера, а у каждого протокола в `containers` есть `last_config`: это клиентский конфиг, записанный строкой JSON внутри JSON.

Для AmneziaWG адрес сервера хранится в нескольких местах:

- `hostName` в корне ключа;
- `hostName` и `port` в `last_config`;
- строка `Endpoint = IP:порт` в тексте конфига `last_config.config`;
- `port` у самого протокола.

Инструменты меняют все эти поля согласованно. В остальных протоколах (XRay, OpenVPN и других) старый адрес заменяется везде внутри `last_config`, а порт не меняется. Стиль записи `last_config` сохраняется: с отступами, как в AmneziaVPN 4.x, или компактный, как в 5.x.

При переводе в `conf` вместо заглушек `$PRIMARY_DNS` и `$SECONDARY_DNS` подставляются DNS из ключа (по умолчанию `1.1.1.1` и `1.0.0.1`). Если в тексте нет строки `MTU`, она добавляется из ключа.

Обратный путь из `conf` в `link` повторяет импорт `.conf` в самом приложении:

- контейнер `amnezia-awg`, а если параметров обфускации нет — `amnezia-wireguard`;
- флаг `isThirdPartyConfig`;
- DNS из строки `DNS`;
- MTU 1376, если он не задан в конфиге (как в настольной версии приложения).

Список параметров AmneziaWG (`Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `H1`–`H4`, `I1`–`I5` и более новые) взят из исходников клиента AmneziaVPN.

## Ограничения

Менять IP и порт имеет смысл, только если это тот же сервер с теми же ключами: сменился адрес или проброшен другой порт. Если сервер переустановлен или протокол пересоздан, старые ключи уже недействительны, и нужен новый ключ из приложения.

Прочие ограничения:

- Порт и формат `conf` поддерживаются только для AmneziaWG и WireGuard.
- Ключ с полным доступом хранит доступ к серверу по SSH, а не клиентский конфиг, поэтому в `conf` его не перевести.
- Ключи Amnezia Premium и Amnezia Free не содержат готового конфига сервера: приложение получает его с серверов Amnezia, так что менять в них нечего.
- Если в конфиге несколько секций `[Peer]`, меняется только первый `Endpoint`.

## Безопасность

В ключах и конфигах лежат приватный ключ клиента и PresharedKey. С ними можно подключиться к вашему серверу, поэтому не коммитьте их в репозиторий и не вставляйте в сторонние онлайн-сервисы. Чтобы файлы не попали в git случайно, добавьте в `.gitignore`:

```gitignore
*.vpn
*.conf
```

Страница и утилита работают только локально и не делают сетевых запросов.
